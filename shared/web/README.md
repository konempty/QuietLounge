# shared/web — 라운지 페이지 inject JS 의 단일 소스

QuietLounge 가 4 개 플랫폼(Chrome ext / Safari ext iOS+macOS / iOS native WebView / Android WebView) 에서
라운지 페이지에 주입하는 content-script 의 **공통 source of truth**.

각 플랫폼 entry (`entries/*.ts`) 가 esbuild 로 IIFE 빌드되어 4 개 위치로 in-place 출력된다:

| 플랫폼                    | 산출물 경로                                                                              |
|------------------------|-------------------------------------------------------------------------------------|
| Chrome                 | `chrome-extension/content-scripts/main.js`                                          |
| Safari ext (iOS+macOS) | `safari-extension/QuietLounge/Shared (Extension)/Resources/content-scripts/main.js` |
| iOS native WebView     | `safari-extension/QuietLounge/iOS (App)/Resources/webview-scripts/after.js`         |
| Android WebView        | `android-app/app/src/main/assets/webview-scripts/after.js`                          |

**위 4 파일은 빌드 산출물이다 — 절대 직접 편집하지 말 것**. 헤더 주석에 `auto-generated by scripts/build.mjs`
표시 + ESLint ignore + CI drift 가드. 편집은 항상 `shared/web/` 안에서 한 뒤 `pnpm build` 로 반영.

## 디렉토리 구조

```
shared/web/
├── core/                       # 4 플랫폼 공통 순수 함수 (현재 PR — Tier 1)
│   ├── selectors.ts            # SEL DOM 셀렉터 상수
│   ├── storage-keys.ts         # 스토리지 키 상수 3 개
│   ├── pages.ts                # isActivePage / isBlockButtonPage
│   ├── cleanbot.ts             # isCleanbotFiltered (가장 최근 추가된 cross-platform 가드)
│   ├── block-check.ts          # isBlocked(blockData, personaId, nickname)
│   └── style.ts                # applyStyle(el, blocked, mode)
├── entries/                    # 플랫폼별 esbuild 진입점 (각각 IIFE 출력)
│   ├── chrome.ts               # Chrome ISOLATED world content-script
│   ├── safari-ext.ts           # Safari ext (iOS + macOS) content-script
│   ├── ios-after.ts            # iOS native WebView afterScript
│   ├── android-after.ts        # Android WebView after.js
│   └── placeholders.d.ts       # __QL_BLOCK_DATA_PLACEHOLDER__ ambient 선언
└── platform/                   # 어댑터 인터페이스 — 후속 PR 에서 채움
    └── adapter.ts              # PlatformAdapter (storage / bridge / confirm / btn)
```

## 빌드 / 테스트 명령

```bash
pnpm build           # 4 산출물 동시 빌드 (~수십 ms)
pnpm build:watch     # 개발용 watch 모드
pnpm build:check     # 빌드 + drift 검출 (산출물 != git 이면 fail)

pnpm test            # vitest run — shared/web/ 단위 테스트 + artifacts 가드 포함
./run-tests.sh       # 빌드 + drift + 풀 테스트 + Android + Swift + Lint
```

## 새 chunk 마이그레이션 9 단계

같은 패턴이 후속 PR (#2 filter-engine, #3 inject-buttons, #4 profile-stats 등) 에서 반복:

1. `core/` 또는 `features/` 에 순수 함수로 추출 (TypeScript)
2. `tests/shared/web/<name>.test.ts` 작성 — JSDOM 단위 테스트
3. 4 개 entry (`entries/*.ts`) 의 inline 정의를 shared import 로 교체
   - Chrome: `chrome.storage.local` 등을 그대로 사용하되 shared 함수에 closure 변수 wiring
   - Safari ext: `browser.*` + `__QL_storage` 분기 유지
   - iOS / Android: placeholder + native bridge 호출 유지
4. 플랫폼 차이가 있으면 `platform/adapter.ts` 에 인터페이스 추가
   - 후속 PR #3 부터 본격 사용 — 현재 PR 은 스캐폴딩만
5. `pnpm build` — 4 산출물 갱신
6. `pnpm test` — 새 단위 테스트 + cleanbot-skip source guard + artifacts 가드 통과
7. **Manual smoke** (4 플랫폼 1 회씩):
   - Chrome: unpacked load → 라운지 → 차단 / 해제 동작
   - Safari macOS: Xcode "QuietLounge (macOS)" Run → 시스템 설정 활성화 → 라운지
   - iOS native: Xcode "QuietLounge (iOS)" 시뮬레이터 → 차단 / placeholder 치환 확인
   - Android: `./gradlew :app:installDebug` → 차단 / placeholder 치환 확인
8. `git diff --stat` 으로 산출물 변경 확인 (PR 설명에 첨부)
9. `pnpm build:check` 로 drift 없음 확인 후 commit

## 4 플랫폼 차이 cheat sheet

| 항목            | Chrome                       | Safari ext                                             | iOS native                                          | Android                                        |
|---------------|------------------------------|--------------------------------------------------------|-----------------------------------------------------|------------------------------------------------|
| storage       | `chrome.storage.local` (cb)  | `browser.storage.local` (Promise) + `__QL_storage` 브릿지 | placeholder + `webkit.messageHandlers.qlBridge`     | placeholder + `window.QuietLounge.postMessage` |
| bridge        | `chrome.runtime.sendMessage` | `browser.runtime.sendMessage`                          | `webkit.messageHandlers.qlBridge.postMessage(JSON)` | `window.QuietLounge.postMessage(JSON)`         |
| confirm       | native `confirm()`           | `qlConfirm` DOM modal (iOS Safari 의 confirm 봉쇄 우회)     | native bridge → UIAlertController 콜백                | native bridge → AlertDialog 콜백                 |
| btn 클래스       | `quiet-lounge-btn`           | `quiet-lounge-btn`                                     | `ql-btn`                                            | `ql-btn`                                       |
| MAIN world 분리 | yes (api-interceptor.js)     | yes (별도 inject)                                        | n/a                                                 | n/a                                            |
| placeholder   | n/a (storage 비동기 로드)         | n/a                                                    | `__QL_BLOCK_DATA_PLACEHOLDER__`                     | `__QL_BLOCK_DATA_PLACEHOLDER__`                |

## placeholder 보존 메커니즘 (iOS / Android)

iOS Swift `WebViewScripts.swift` 의 `afterScript(blockData:filterMode:)` 와
Android Kotlin `WebViewScripts.buildAfter()` 가 산출물 텍스트를 읽고 다음 두 토큰을 치환:

- `__QL_BLOCK_DATA_PLACEHOLDER__` → JSON 직렬화된 차단 목록 (대치 위치는 `window.__QL_BLOCK_DATA = ...` 의 RHS)
- `'__QL_FILTER_MODE_PLACEHOLDER__'` → `'hide'` 또는 `'blur'` (string literal 통째로 치환)

esbuild 는 미정의 글로벌 식별자를 그대로 통과 + string literal 내부를 절대 건드리지 않으므로
산출물에 두 토큰이 보존된다. `tests/build/artifacts.test.js` 가 회귀 가드.
`shared/web/entries/placeholders.d.ts` 가 TypeScript 타입체커용 ambient 선언을 제공
(entry 파일 상단 `// @ts-nocheck` 와 함께 작동).
