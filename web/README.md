# web — 라운지 페이지 inject JS 의 단일 소스

QuietLounge 가 4 개 플랫폼(Chrome ext / Safari ext iOS+macOS / iOS native WebView / Android WebView)
에서 라운지 페이지에 주입하는 모든 .js 의 **공통 source of truth**.

각 entry (`entries/*.ts`) 는 esbuild 로 IIFE 번들되어 *in-place 산출물*로 출력 — manifest / 코드 변경 없이
산출물만 갱신된다.

## 산출물 매핑 (10 타깃)

| 카테고리 | 플랫폼 | entry | 산출물 경로 |
|---|---|---|---|
| 메인 | Chrome | `chrome.ts` | `chrome-extension/content-scripts/main.js` |
| 메인 | Safari ext | `safari-ext.ts` | `safari-extension/.../content-scripts/main.js` |
| 메인 | iOS native | `ios-after.ts` | `safari-extension/.../iOS (App)/Resources/webview-scripts/after.js` |
| 메인 | Android | `android-after.ts` | `android-app/.../assets/webview-scripts/after.js` |
| before | iOS native | `ios-before.ts` | `.../webview-scripts/before.js` |
| before | Android | `android-before.ts` | `.../webview-scripts/before.js` |
| api-interceptor | Chrome / Safari ext | `web-api-interceptor.ts` | 두 outfile (chrome / safari) |
| Safari ext 전용 | — | `safari-injector.ts` | `.../content-scripts/injector.js` |
| Safari ext 전용 | — | `safari-storage-bridge.ts` | `.../content-scripts/storage-bridge.js` |

**모든 산출물은 자동 생성 — 직접 편집 금지**. 헤더에 `auto-generated by scripts/build.mjs` 표시 + ESLint
ignore. 산출물은 `.gitignore` — 모든 빌드 진입점 (Android Gradle `preBuild` hook / GitHub Actions /
Safari Xcode 빌드 전 수동) 이 esbuild 를 선행 호출. 편집은 `web/` 안에서 하고 `pnpm build`.

## 빌드 / 테스트 명령

```bash
pnpm build           # 10 산출물 동시 빌드 (~수십 ms)
pnpm build:watch     # 개발용 watch 모드

pnpm test            # vitest run — web/ 단위 테스트 + artifacts 가드 포함
./run-tests.sh       # 빌드 + 풀 테스트 + Android + Swift + Lint
```

## 4 플랫폼 차이 cheat sheet

| 항목 | Chrome | Safari ext | iOS native | Android |
|---|---|---|---|---|
| storage | `chrome.storage.local` (cb) | `browser.storage.local` (Promise) + `__QL_storage` 브릿지 | placeholder | placeholder |
| bridge | `chrome.runtime.sendMessage` | `browser.runtime.sendMessage` | `webkit.messageHandlers.qlBridge` | `window.QuietLounge.postMessage` |
| confirm | native `confirm()` | `qlConfirm` DOM modal | native bridge → UIAlertController | native bridge → AlertDialog |
| btn 클래스 | `quiet-lounge-btn` | `quiet-lounge-btn` | `ql-btn` | `ql-btn` |
| MAIN world 분리 | manifest `world: "MAIN"` | injector.js 동적 `<script>` | n/a | n/a |
| placeholder | n/a | n/a | `__QL_BLOCK_DATA_PLACEHOLDER__` | `__QL_BLOCK_DATA_PLACEHOLDER__` |

## placeholder 보존 메커니즘 (iOS / Android)

iOS Swift `WebViewScripts.afterScript(blockData:filterMode:)` 와 Android Kotlin
`WebViewScripts.buildAfter()` 가 산출물 텍스트를 읽고 다음 두 토큰을 치환:

- `__QL_BLOCK_DATA_PLACEHOLDER__` → JSON 직렬화된 차단 목록
- `__QL_FILTER_MODE_PLACEHOLDER__` → `hide` 또는 `blur` (bare token, 따옴표는 산출물 그대로)

esbuild 는 미정의 글로벌 식별자를 그대로 통과시키므로 산출물에 토큰이 살아남는다. iOS Swift 의
`beforeScript()` 도 Bundle 의 `before.js` 산출물을 직접 로드 (PR #5).
`tests/build/artifacts.test.js` 가 모든 산출물의 회귀 가드.

## 새 chunk 추가 패턴

1. `core/<name>.ts` 에 순수 함수로 추출 (TypeScript, jsdom 으로 단위 테스트 가능하도록)
2. 플랫폼 차이는 `platform/adapter.ts` 의 인터페이스로 흡수 — entry 가 구현 객체를 만들어 주입
3. `tests/web/<name>.test.ts` 작성 — JSDOM 단위 테스트 + 엣지 케이스 가드
4. 4 entry 의 inline 정의를 shared 호출로 교체
5. `pnpm build` → 산출물 갱신 → `./run-tests.sh` 그린 확인
6. 4 플랫폼 manual smoke (Chrome unpacked / Safari Xcode Run / iOS 시뮬레이터 / Android `:app:installDebug`)
